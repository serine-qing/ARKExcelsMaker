# 干员技能数据获取计划

## 目标

生成技能识别所需的本地静态数据：

- 可识别的干员名单。
- 干员 ID、中文名和技能列表。
- 技能 ID、中文名和标准图标。
- 标准图标的预计算哈希。
- 数据来源版本和缺失资源报告。

生成结果随网页部署，运行时不依赖 PRTS 或第三方接口。

## 数据源选择

### 推荐主数据源

[yuanyan3060/ArknightsGameResource](https://github.com/yuanyan3060/ArknightsGameResource)

该仓库已经提供：

```text
gamedata/excel/character_table.json
gamedata/excel/skill_table.json
gamedata/excel/char_patch_table.json
skill/*.png
version
```

相较于 PRTS，它的优势是：

- 数据与游戏内部 ID 对应，便于自动关联。
- 技能图标集中存放，不需要逐页解析。
- 可以按仓库版本增量同步。
- 不会对 PRTS Wiki 服务器造成批量请求压力。

### 备选数据源

- [Kengxxiao/ArknightsGameData](https://github.com/Kengxxiao/ArknightsGameData)：适合获取游戏数据表，但技能图标需要从其他资源仓库补充。
- [ArknightsAssets/ArknightsAssets2](https://github.com/ArknightsAssets/ArknightsAssets2)：可作为资源缺失时的备用图标来源。
- [PRTS Wiki API](https://prts.wiki/api.php)：仅用于人工核对或补充缺失项，不作为主要批量数据源。

## 实现步骤

### 1. 编写资源同步脚本

在项目中增加开发期脚本：

```text
scripts/sync-arknights-data.mjs
```

脚本负责：

1. 获取来源仓库当前版本或 commit SHA。
2. 下载角色表、技能表和升变角色表。
3. 获取需要的技能图标。
4. 校验文件完整性。
5. 生成浏览器使用的数据和图片。

优先采用 Git sparse checkout、GitHub API 或仓库压缩包，不逐页抓取 Wiki HTML。

### 2. 筛选正式干员

从 `character_table.json` 中筛选可用角色：

- 排除敌人、召唤物、陷阱和剧情 NPC。
- 排除没有展示名称的内部角色。
- 保留正式可显示干员。
- 处理阿米娅等升变形态。
- 保留角色 ID、中文名、职业、稀有度和技能引用。

筛选规则不能只依赖一个字段，应生成候选列表供首次人工核对。

### 3. 建立干员和技能映射

基本关联流程：

```text
character_table[characterId].skills[].skillId
→ skill_table[skillId]
→ 技能名称、iconId
→ skill/skill_icon_<图标ID>.png
```

图标 ID 可能存在例外，按以下顺序尝试：

1. 技能数据中的 `iconId`。
2. 角色技能配置中的 `overridePrefabKey`。
3. `skillId` 本身。

每个候选路径都需要检查文件是否存在。找不到图标时写入报告，不能静默跳过。

### 4. 处理特殊情况

重点验证：

- 阿米娅等存在升变或补丁数据的角色。
- 共用技能图标的多个角色。
- `iconId` 为空的技能。
- 角色只有一个或两个技能。
- 活动、联动和不可获取角色。
- 新版本新增但资源尚未同步的技能。

`char_patch_table.json` 应参与映射生成，避免只解析基础角色表造成遗漏。

### 5. 优化图片

对最终使用的图标执行：

1. 保留原始 PNG 作为生成输入。
2. 转换为统一尺寸的 WebP。
3. 去除未被任何正式干员引用的图标。
4. 计算标准图标的 pHash/dHash。
5. 计算颜色直方图或简化后的颜色特征。

建议输出：

```text
public/skills/<skillId>.webp
public/data/operators.json
public/data/data-version.json
```

### 6. 生成前端索引

目标格式示例：

```json
[
  {
    "characterId": "char_103_angel",
    "name": "能天使",
    "profession": "SNIPER",
    "skills": [
      {
        "skillId": "skchr_angel_1",
        "name": "冲锋模式",
        "icon": "/skills/skchr_angel_1.webp",
        "hash": "f0c39a...",
        "colorFeature": [0.12, 0.08, 0.21]
      }
    ]
  }
]
```

另外生成版本文件：

```json
{
  "source": "yuanyan3060/ArknightsGameResource",
  "commit": "<commit-sha>",
  "gameDataVersion": "<version>",
  "generatedAt": "<ISO date>",
  "operatorCount": 0,
  "skillCount": 0,
  "missingIconCount": 0
}
```

### 7. 生成校验报告

脚本完成后输出：

```text
reports/arknights-data-report.json
```

报告包含：

- 被保留和排除的角色数量。
- 没有技能的角色。
- 找不到技能定义的 ID。
- 找不到图标的技能。
- 重复名称或重复 ID。
- 未被引用的技能图标。
- 输入与输出文件校验值。

当存在关键缺失项时，脚本应以非零状态退出，避免发布不完整数据。

### 8. 增量更新

更新时：

1. 比较来源 commit SHA 或版本文件。
2. 来源未变化时跳过处理。
3. 只重新转换新增或变化的图标。
4. 删除已失效且不再被引用的输出。
5. 重新生成索引和校验报告。

可在手动命令或 CI 中执行，但不应由普通网页访问触发。

## PRTS 备用获取方案

如果资源仓库确实缺少某项数据，使用标准 MediaWiki API：

```text
https://prts.wiki/api.php
```

建议流程：

1. 通过 API 查询指定干员页面或文件名。
2. 使用 `imageinfo` 获取原始图片 URL。
3. 缓存 API 响应和图片。
4. 设置明确的 User-Agent。
5. 限制请求频率并设置重试间隔。
6. 只请求缺失项，不重复抓取完整 Wiki。

不要使用 HTML 爬虫批量解析干员页面。Wiki 模板和页面结构可能变化，稳定性也低于游戏数据 ID 映射。

## 验收标准

- 能生成完整的正式干员名单及技能映射。
- 每项技能都具有名称、技能 ID 和可访问的本地图标。
- 标准图标已转换并预计算匹配特征。
- 所有缺失和异常项都有明确报告。
- 再次执行脚本可稳定复现同样结果。
- 前端运行时不请求 GitHub、PRTS 或其他外部数据源。
